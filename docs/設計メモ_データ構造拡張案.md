# 工事工程アプリ　設計メモ（第2版）

作成：2026-11-27　ベース：工程管理ガントチャート（HTML単体＋共有フォルダ版）

---

## 0. 目標とする業務の流れ（2026-11-27 決定）
1. 積算の**設計内訳書**または**入力データリスト**を読み込み、工種・種別・細別・数量・歩掛から工程表のベースを作る
2. 各歩掛の日当り施工量から施工日数を算定する（雨休率・班数を見込んで暦日数に換算）
3. 出そろったデータを基に、人が先行・後続をつないで工程を組む
4. 工程計画作成支援システムで読み込める **XML形式で出力**する
5. さらに発注資料用として、**工種だけの工程概要資料をExcelで作成**する

## 0-1. 決定事項
| 項目 | 決定 |
|---|---|
| 日数の数え方 | XML方式（工程計画作成支援システム方式）だけに絞る。土日祝は雨休率に含め、カレンダーでは数えない |
| 1タスクの複数期間 | 細別の下に下位工程を行として作り、細別は合計にする（11-28 変更。1行に分かれたバーを並べる方式は取りやめ） |
| XMLの扱い | 元のXMLは無い前提。本アプリで作った工程から一から XML を生成し、他システムで読み込めるようにする |
| XMLの書式 | 受領ファイル（システム出力の生データ）に合わせる：宣言 `encoding="Shift_JIS"`、中身は UTF-8、改行 CRLF、2スペース字下げ |

## 1. 受領資料から分かったこと

### 1-1. XML（工程計画情報参考資料）
国交省の工程計画作成支援システムが書き出す形式（`<ファイル名 形式="2019.01">`）。

| ブロック | 内容 | 本アプリでの扱い |
|---|---|---|
| 鏡ブロック | 工事名、工事地名、工期自・至、日数、雨休率、事業区分、工事区分、整備局、対象工事区分（A、b、準備日数、後片付日数） | 「工事情報」として保持 |
| 体系ブロック | 体系をレベル1〜4で入れ子（工事区分／工種／種別／細別）。レベル4に工程（期間）、その下のレベル6に歩掛 | 階層タスクに対応 |
| 休日ブロック | `河川の出水期,6,1,2026,9999,10,31,1`（名称, 開始月, 日, 開始年, 終了年, 終了月, 日, フラグ） | 毎年くり返す作業不能期間 |
| 制限制約ブロック | 今回は空 | 出力時は空で書く |
| 設定ブロック | 日数表示、色設定 | 既定値で書く |

**レベル4（工程を持つタスク）の主な項目**
- 名称・規格・数量・単位・区分・番号（番号はXML内で一意のID）
- 工程履歴：日当り作業量、標準作業日数、雨休率、休日（1＝作業不能期間の対象）
- 期間（最大3つ）：開始・終了（工期初日を1日目とする通し日番号）、日数、班数、雨休（日数）、接続（先行の「番号,期間」）、接続子（後続）、接続点、接続日

**レベル6（歩掛）**：コード（例 CB210120）、枝番、施工条件、日当り施工量、施工日数、J条件（設問・回答）

### 1-2. 計算ルール（実データで照合済み）
- 施工日数＝数量÷日当り施工量（例：掘削 8,500÷350＝24.29日）
- 雨休日数＝切り上げ（施工日数×雨休率）（例：24.29×0.9＝21.86→22日）
- 暦日数＝（施工日数＋雨休日数）÷班数（例：伐竹 (40.77＋37)÷3＝25.9→26日）
- 出水期は「休日＝1」のタスクだけを止める（準備工・余裕期間・後片付けは休日＝0）。敷鉄板は71日目に着手可能でも出水期明けの217日目から施工
- 接続点1＝先行の完了から、接続点0＝先行の開始から。接続日は日数のずれ（例：集積積込みは除根整地の開始＋2日）
- 端数は持ち越して積み上げ、表示上の完了日だけ切り上げ（掘削の完了 272.29 → 273日目、続く法面整形は 272.29＋11.71＝284.0 → 284日目）。**本アプリは現在タスクごとに切り上げており、端数の持ち越しは未対応**（1日程度ずれる場合あり）
- レベル4の標準作業日数は、配下の歩掛の合計の場合（除根整地＝除根＋整地）と、代表の歩掛1つの場合（覆土）がある

### 1-3. Excel（全体工程表）
- 左：No.／工種／上段 種別・下段 細別／単位／数量。1項目2行
- 右：20日ごとの日番号と日付の目盛り、出水期を橙で網掛け
- バーの上に「名称_暦日数日」、下に開始・完了の日番号
- 赤：通常の工程、青：クリティカルパスと読める。工程間は破線の縦線（パスライン）

## 2. データ構造（実装済みの部分は ✅）

### 2-1. 工事情報 ✅ `settings.koji`
```js
koji:{place, from, to, rainRate:0.9, jigyo, kubun, kyokuCode, kyokuName, taishoName, A, b, prep, clean}
```
工事名は `title`。工期日数は from〜to から計算。

### 2-2. 作業不能期間 ✅ `settings.periods`
```js
{name:'河川の出水期', from:'2026-06-01', to:'2026-10-31', yearly:true, y0:2026, y1:9999}
```
- `restricted!==false` のタスクだけ、この期間を飛ばして日程を組む
- 土日祝（sat/sun/nat）は表示の色分け・網掛け専用（`view.shadeWeek`）

### 2-3. タスク ✅（segs・site・xmlNo は未使用）
```js
{
  spec:'', qty:'', unit:'',
  daily:'',            // 日当り施工量
  parties:1,           // 班数
  durSrc:'yield'|'work'|'fixed',  // 数量÷日当り ／ 施工日数を入力 ／ 暦日数を直接
  work:5,              // 施工日数（durSrc='work' のとき）
  rainRate:'',         // 空欄＝工事の既定
  restricted:true,     // 作業不能期間の対象（XMLの「休日」）
  buk:[{code,eda,name,unit,daily,cond,J:[[設問,回答]…]}],
  segs:[…], site:'', xmlNo:null
}
```
- バーの端をドラッグ、または完了予定日を直接変えると `durSrc='fixed'` に切り替わる（詳細設定で計算に戻せる）

### 2-4. 先行・後続
- 既存の `startRule`（参照先・開始／完了・±日数）をそのまま使う
- XMLの `接続=13,1／接続点1／接続日1` ↔ `{ref, base:'end', offset:1}`
- 期間2以降への接続（`41,2`）は `{ref, seg:2, base, offset}` とする予定

### 2-5. クリティカルパス（未実装）
- 関係を有向グラフとして前進・後退計算し、各タスクの全余裕（TF）を求める
- 基準は工期至。TF＝0 をクリティカル、TF＜0 を工期超過として表示し、青で強調

## 3. XML出力の方針
- 本アプリの工程から一から生成（元XMLは前提にしない）
- 階層 → 体系（レベル1〜4）。レベル4にあたるタスクに工程履歴・期間を書き、`buk` からレベル6の歩掛を書く
- 番号は出力時に通し番号を振る（`xmlNo` があれば優先）
- 日付 → 工期初日を1日目とする通し日番号
- 書式は受領ファイルに合わせる（宣言 Shift_JIS・中身 UTF-8・CRLF・2スペース字下げ）
- 階層の深さがレベル4に満たない・超える場合の扱いは要検討（入力データリスト読み込みとあわせて決める）

## 4. 全体工程表・工程概要資料
- 全体工程表：受領Excelと同じ構成で印刷（A3横・PDF）
- 工程概要資料（発注資料用）：工種単位のバーだけを Excel に出力

## 5. 段取りと進み具合
1. ✅ 工事情報・数量・歩掛・雨休率・班数の項目と日数の自動計算、作業不能期間（毎年・対象指定）、工期の表示
2. ✅ 下位工程（細別の下に作り、細別は合計）
3. ✅ クリティカルパス（余裕日数は未）
4. ✅ 入力データリスト（PDF）の読み込み → 工程表のベース作成、日当りマスタとの連携
5. XML出力（受領XMLの読み込みも作り、往復で照合して検証）
6. 全体工程表の印刷レイアウト
7. 工種別の工程概要資料（Excel）

## 6. 入力データリストの読み込み方針（2026-11-27）
- 業務PCでexeは動かせるが、手順は少ないほうがよい → **exeは作らず、HTMLの中でPDFを読む**（pdf.js を埋め込み、オフラインで動かす）
- 読み取りの手順は SoukatsuCheck（akkey1223/SoukatsuCheck、Python＋PyMuPDF）の `parse_inp.py`・`pdfgeom.py`・`parse_common.py` をそのまま JavaScript に移す
  - 文字：pdf.js の getTextContent（文字ごとの位置は文字列の幅から按分）
  - 罫線：pdf.js の getOperatorList から線・細い矩形・枠の矩形を拾い、同一直線上の線分をつなぐ
  - 見出し（区分・工事区分・工種・種別・単位・数量・摘要・入力条件）と縦横の罫線で列・行を決める
  - 区分欄が空の枠は直前の項目の続き（ページ跨ぎ）として連結
  - 区分 1〜4 → 工事区分・工種・種別・細別、(1) の 6P・標準・独自 → 細別にぶら下がる歩掛
  - 歩掛はコード（摘要欄）、J条件（入力条件欄）、単位数量（摘要欄）を取り出す
- **日当り施工量は入力データリストに載っていない**ため、別に用意する
  - 主な出どころ：同じプロジェクトの「歩掛 日当り施工量 抽出アプリ」が積算基準書（共通編 Ⅰ-14-④ 作業日当り標準作業量）から作る JSON（`codes[].code` → `daily[]`：項目・条件・値・単位・出典頁・確度）。詳細は「歩掛日当り抽出アプリ_メモ」
  - 工程アプリは年度ごとの JSON を「日当りマスタ」として読み込む。歩掛コードで候補を引き、J条件の文言と `daily[].cond` を照らして候補を絞り、人が選んで確定する（確度B・Cは注意表示）
  - 工程計画作成支援システムのXML（コード・施工条件・J条件・日当り施工量の組）も補助として読み込めるようにする
  - 独自歩掛は歩掛見積依頼書に日当り施工量がある（SoukatsuCheck の parse_irai.py が読める）→ 後の段階で対応
- 検証用に、受領XMLと同じ工事の入力データリストPDFが必要

## 7. 入力データリストの取り込み（2026-11-27 実装）
- `app/src/inpparse.js`：SoukatsuCheck の pdfgeom.py・parse_common.py・parse_inp.py を pdf.js 用に移植。受領した入力データリスト（R8由良川栗町地区他、93ページ）で Python 版と照合し、435項目中433項目が一致。残り2件（伐木除根のJ条件。条件名が途中で切れて値との間が空白1つ）は Python 版で取れていない条件を JS 版で取れている差
  - pdf.js は空白を別の要素に分け、長い空白は落とすため、同じ行で縦罫線をまたがない要素をつなぎ、すき間の幅から空白を戻して PyMuPDF と同じ「1マス＝1スパン」にしている
  - フォントは Adobe-Japan1 の CID（ToUnicode なし）なので、CMap（Adobe-Japan1-UCS2 ほか日本語分）を埋め込んでいる
- 工程表への変換（「入力データリスト取込」ボタン、管理者）
  - 区分1〜4 → 工事区分・工種・種別・細別のタスク。細別に数量・単位・規格、歩掛（(1) の 6P・標準・独自）を `buk` として持たせる
  - 集計の行（直接工事費・共通仮設費・工事価格・消費税相当額など）は、取り込む範囲のチェックを初めから外す
  - 日当り施工量
    - 施工歩掛・独自歩掛：内訳の「運転」など単位が日の行の日数から算出（例：不整地運搬車 0.366日／100m3 → 273.22m3/日。受領XMLの273と一致）
    - 施工パッケージ：日当りマスタ（`_日当りマスタ_R08.json`、共有フォルダ）からコードで引き、J条件と条件の文言を照らして1つに決まれば自動で入れる。項目名が違うとき（伐木除根の「樹木・竹の区分」⇔「作業名」）は値の文字の似かたで決める（伐木（機械施工）2280・伐竹439。受領XMLと一致）
  - 細別の施工日数＝数量×数量比÷日当り施工量を、「日数に使う」にチェックした歩掛ぶん合計（初めは日数が最も長い1つ）。`durSrc:'buk'`
  - 開始日は全部工期（自）にそろえ、先行・後続は人がつなぐ
- 日当りマスタは「書き出し・読み込み」から登録、工事情報で使う年度を選ぶ（空欄＝最新）

## 8. クリティカルパス（2026-11-27 実装）
- 予定完了日が最も遅い末端のタスクから、日付を決めている関連付けだけをさかのぼる（開始日で拘束のタスクは開始日の関連付けへ、完了日で拘束・両方で拘束は完了日の関連付けへ）
- 「決めている」＝基準から計算した日付が、そのタスクの日付と一致している関連付け（複数基準なら最も遅い／早い日を決めたもの）。指定日で決まっていればそこで終わる
- 線は関連付けの基準どおりに引く（あきひろ指定）：完了→開始、**開始日同士は開始日→開始日、完了日同士は完了日→完了日**、開始→完了
- 予定パスも同じ規則で引く（リンクに `how`：es／ss／ee／se を保存。従来のリンクは es）
- 表示：ツールバー「クリティカルパス」で切替。色は「作業不能期間・色」で変更（既定 #e11d48）。バーは枠、線は太線＋矢印

## 9. アンカー（日程の基準工程）と逆算（2026-11-27 実装）
- 工程の優先順位を分かりやすくするため、**アンカーにする工程を明示的に選ぶ**方式（開始日の指定の有無から自動判断する案は取りやめ）
- タスクに `pin`（アンカーの開始日）を持たせる。ツールバー「⚓ アンカー」または詳細設定で設定・解除
- アンカーは pin の日付から動かない（自身の関連付けは使わない）
- アンカーの前工程（関連付けをたどってアンカーにつながる工程）は、関連付けの向きを逆にして後ろの工程に合わせて決める（逆算）。前工程が複数の後工程につながるときは最も早い日
- アンカーより後の工程は、従来どおり関連付けのとおり（順算）
- アンカーにつながらない工程は従来どおり
- 逆算の工程をドラッグ・日付変更すると、日付の代わりに関連付けの日数（オフセット）を変える
- 表示：アンカーは橙（⚓）、逆算は紫、通常の関連付けは青。クリティカルパスはアンカーで止まり、逆算の関係は後ろの工程から前の工程へ引く

## 10. 並び・表の列（2026-11-27）
- 並び：入力順／工程区分順（工程順＝開始予定日順は削除）
- 工程区分順：工程区分ごとに見出し行（区分の中のタスクをまとめたバー）を置き、区分の中は設計書（入力）の並び。見出しは表示だけの行で、折りたためる
- 左の表の No. は非表示（内部の番号は詳細設定・メッセージで使用）。「工程区分」の列を追加
- パスの線は関連付けの内容（実際に使われている側）から点を決める

## 11. 余裕期間・準備工・跡片付け（2026-11-27、11-28に名称変更）
- 工事区分のレベルに「日数だけの工程」（`frame`：yoyu／prep／clean）を置く。先頭に余裕期間・準備工、最後に跡片付け
- 日数は工事情報（余裕期間・準備工・跡片付け（日））。左の表の暦日数を書き換えると工事情報の値が変わる
- 雨休率・作業不能期間は使わず暦日で数える（工程計画作成支援システムの「休日＝0」に相当）
- 開始日：余裕期間＝工期（自）、準備工＝余裕期間の翌日、跡片付け＝ほかの工程がすべて終わった翌日
- アンカーより前で準備工が逆算になるときは、余裕期間も準備工の前に逆算で置く。工期（自）より前に始まる工程には警告（!）を出す
- 入力データリストの取り込み・新しい工事の作成で自動で置く。既存の工事は工事情報の「…工程を工事区分のレベルに置く」にチェックして反映

## 12. 工程区分・表示の設定（2026-11-28 実装）
- 工程区分は番号（1以上の整数、既定は1）。親の番号を変えると、同じ番号だった子も変わる
- 行の右クリックで工程区分を分ける：直系の上位（工事区分〜）と、押した行より下（歩掛を含む）をコピーし、跡片付けの前に置く。同じ区分にコピー済みの上位があれば使い回す。コピーは元の行を src に持ち、工程区分順では区分の中を元の設計書の並びにする。日程は元の工程の翌日からの日付指定、関連付け・実績は引き継がない
- 「表示の設定」ポップアップ：左の表、階層の表示（親のまとめのバー／畳んだ行の子ごとの行）、パス、バーの文字、休日の網掛け

## 13. 下位工程（2026-11-28。1行に分けたバーを並べる「期間」の方式は取りやめ）
- 1行の中で分かれたバーを並べる方式（期間）はやめ、細別の下に普通の行として下位工程（設置・撤去など）を作り、細別は下位工程の合計にする（あきひろ指定）
- 細別の行：施工日数の欄は下位の工程の施工日数の合計（斜体）、暦日数・開始・完了は全体の期間（下位工程の水平投影）。詳細設定に下位工程の一覧と合計（施工日数・暦日数の合計）を表示
- 下位工程は普通の子タスク（関連付け・アンカー・クリティカルパス・ドラッグ・実績はそのまま）。`bukUse` を持ち、細別の歩掛のうち日数に使うものを選ぶ（日当り・数量比の変更は細別とほかの下位工程にも反映）
- 操作：ツールバー「下位工程を作る」／詳細設定「下位工程を作る…」「＋下位工程を追加」「下位工程をやめて1本に戻す」。数は2〜6（個数の上限なし。追加の数量は細別の数量の残り）
- 作るときの数量：「数量を分ける（合計＝細別の数量）」／「各下位工程で同じ数量（設置と撤去など）」
- 1つ目は元の日程・関連付け・アンカー・実績を引き継ぎ、2つ目以降は前の完了の翌日から始まる関連付けを入れる
- ほかの工程からの基準・パスの付け替え：開始日の基準は1つ目、完了日の基準は「数量を分ける」なら最後、「同じ数量」なら1つ目
- 以前の期間（`per`）のデータは読み込み時に普通の下位工程として扱う
- XML出力では、下位工程を持つ細別をレベル4、下位工程を期間（最大3）に対応させる方向で検討（4つ以上のときの扱いは要検討）

## 13-2. 作業不能期間をまたぐ工程の描き方（2026-11-28）
- 出水期などに作業できるかは工程ごとに決まるので、工程は1本のバー（1行）のままにする（あきひろ指定）。出水期前・後のために下位工程を作る必要はない
- 作業不能期間の対象の工程は、バー全体＝工程に必要な暦日数＋作業不能期間の日数（日程の計算は従来どおり作業不能期間を飛ばす）
- 表示は作業できる区間だけにバーを描き、作業不能期間はすき間にして細い破線でつなぐ（`C[id].segs`＝作業できる区間、`offd`＝期間内の作業不能日数）
- 暦日数の欄は工程に必要な日数のまま。バー・暦日数の欄にマウスを乗せると「全体 200日（作業 47日＋作業不能期間 153日）」のように表示
- 作業不能期間の対象外の工程は、期間中も続けて1本で描く
- 作業不能期間の網掛けの色は期間ごとに持つ（`periods[].color`）。未設定は登録順の既定の色（橙 #fcd5b4、青 #c9def5、緑 #d4ecc9、紫 #e4d4f2、黄 #f6e7a6、灰 #dcdcdc、桃 #f5c6d0、青緑 #c8ece9 の順）。設定画面の各行で色を選び、「既定」で戻す
- 工程ごとの作業不能期間の扱いは、詳細設定の「作業不能期間には施工しない」で一括切り替え（期間ごとの切り替えは未対応）

## 13-3. バーの表現（2026-11-28）
- 予定のバーごとに塗りと端部の形を選べる（詳細設定「バーの表現」）。色は「バーの色」の設定のまま
  - 塗り `barFill`：''（塗りつぶし）／'up'（斜線 右上がり）／'down'（斜線 右下がり）
  - 端部 `barEnd`：''（通常）／'both'（両端を矢印）。「右端を矢印」は 11-28 に削除（以前のデータは通常として扱う）
- 作業不能期間で区間に分かれたバーは、矢印を最初・最後の区間の端だけに付ける。進捗は形の中に重ねる
- 親のまとめのバー・実施のバーは従来どおり
- バーの色は色見本（16色）から選ぶ：赤・黄・緑・水色・青・紫（明度100%）、同じ6色のパステル、白・灰（淡）・灰（濃）・黒。詳細設定の予定・実施（先頭の「既定」は既定の色）と、「作業不能期間・色」の予定バー・実施バー・親タスクの既定の色。作業不能期間の網掛けの色は従来どおり自由に選ぶ
- 矢印の形は➩（軸を細く、矢じりをバーの高さより少し大きく）。両端を矢印にしたバーで作業不能期間をまたぐ中ほどの区間は軸の太さで描く
- 予定バーの既定の色は水色（#00ffff）。以前の既定（#2563c9）のままの工事は読み込み時に水色に置き換える
- バーはどの色でも枠線を付ける（塗りの色を暗くした色。黒は灰色）。実施のバーも同様（作業中の点線のバーは除く）
- パスの線の色は色見本（パステルを除く6色＋灰（濃）・黒の8色）から選ぶ。予定パス・実施パスの既定は赤（以前の既定のままの工事は赤に置き換え）。クリティカルパスも同じ色見本から選ぶ（既定は従来の #e11d48）
- パスは全部、後に選んだバー（関連付けの後続）側に矢印を付ける。矢印が開始日の文字に隠れないよう、パスの線は文字より上に描き、矢印を少し大きくした
- パスの線の通り道（予定パス・クリティカルパス共通）：先行のバーの端から縦に出て、後続の開始日へは左から（右向きの矢印）、完了日へは右から（左向きの矢印）入る。入る向きと逆側にあるときは行の境目で回り込み、線がバーの上を通らないようにする（完了日どうしの関連付けで線がバーに重なり矢印が見えなかった不具合の対応。test2 の積込→法面整形・分別除去→積込）。完了日に右から入るパスがあるバーは、完了日・名前の文字を右にずらす

## 14. 将来の構想（未実装・2026-11-28）：積算工程モードと実施工程モード
